# EventServiceApi
## Инструкция по запуску проекта

1. Установите .NET SDK версии 10.0 или выше. Вы можете скачать его с официального сайта [.NET](https://dotnet.microsoft.com/download/dotnet/10.0).
2. Склонируйте репозиторий проекта на ваш локальный компьютер.
3. Откройте терминал и перейдите в директорию проекта.
4. Выполните команду `dotnet restore`, чтобы восстановить все зависимости проекта.
5. Выполните команду `dotnet build`, чтобы собрать проект.
6. Выполните команду `dotnet run`, чтобы запустить проект.
7. Выполните команду `dotnet test`, чтобы запустить тесты.
8. После запуска проекта, вы сможете получить доступ к API по адресу `http://localhost:5263`.
9. Доступ к Swagger UI для тестирования API будет доступен по адресу `http://localhost:5263/swagger`.
10. Нужно добавить несколько событий в базу данных, чтобы проверить работу API. Вы можете использовать Swagger UI для добавления событий или использовать Postman для отправки POST-запросов на эндпоинт `/api/events`.
11. Для проверки наличия событий в базе данных, вы можете отправить GET-запрос на эндпоинт `/api/events` через Swagger UI или Postman.
12. Если хотить получить одно событие по его идентификатору, отправьте GET-запрос на эндпоинт `/api/events/{id}`, заменив `{id}` на идентификатор события.
13. Для изменения события, отправьте PUT-запрос на эндпоинт `/api/events/{id}`, заменив `{id}` на идентификатор события, и передайте обновленные данные события в теле запроса.
14. Для удаления события, отправьте DELETE-запрос на эндпоинт `/api/events/{id}`, заменив `{id}` на идентификатор события.
15. Эндпоинт `GET /events` поддерживает фильтрацию и пагинацию через query-параметры:
 

| Параметр   | Тип       | Обязательный | Описание                                        |
|------------|-----------|--------------|-------------------------------------------------|
| `title`    | string    | нет          | Фильтр по подстроке в названии события          |
| `from`     | datetime  | нет          | Нижняя граница даты начала события (включ.)     |
| `to`       | datetime  | нет          | Верхняя граница даты начала события (включ.)    |
| `page`     | int       | нет          | Номер страницы, начиная с 1 (по умолчанию 1)    |
| `pageSize` | int       | нет          | Размер страницы (по умолчанию 10, максимум 100) |

Ответ возвращается в формате `PaginatedResult<T>`:
<code>
<pre>
{
  "items": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "title": "Конференция",
      "startAt": "2026-11-01T10:00:00Z",
      "endAt": "2026-11-01T12:00:00Z"
    }
  ],
  "page": 1,
  "pageSize": 10,
  "totalCount": 42,
  "totalPages": 5
}
</pre>
</code>

Пример запроса:

<code><pre>
curl "http://localhost:5263/events?title=conf&from=2026-01-01&to=2026-12-31&page=1&pageSize=10"
</pre></code>

16. С помощью middleware все ошибки возвращаются в формате Problem Details (application/problem+json):


| Статус | Когда возвращается                                     | Пример title                   |
|--------|--------------------------------------------------------|--------------------------------|
| 400    | Некорректные параметры запроса / нарушение инвариантов | Некорректные параметры запроса |
| 404    | Событие не найдено                                     | Событие не найдено             |
| 500    | Внутренняя ошибка сервера                              | Внутренняя ошибка сервера      |

Пример ответа 400:

<code>
<pre>
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
  "title": "Некорректные параметры запроса",
  "status": 400,
  "detail": "Параметр 'page' должен быть больше нуля.",
  "traceId": "00-8f1c...-01"
}
</pre></code>

Пример ответа 404:
<code>
<pre>
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.4",
  "title": "Not Found",
  "status": 404,
  "detail": "Событие не найдено",
  "traceId": "00-…-01"
}
</pre></code>

Детали исключений пишутся в лог, клиенту отдаётся только обезличенное сообщение.
